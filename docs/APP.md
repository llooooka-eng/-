# تألق (Talluq) — التوثيق الكامل للتطبيق

> تطبيق حجز مواعيد صالونات الحلاقة والتجميل (رجال، نساء، أطفال، وخدمة منزلية).
> مبني بـ **Expo / React Native**، عربي أوّلاً (RTL)، بهوية لؤلؤية/حبرية ولمسة ذهبية «تألق».

- **المنصّات:** iOS · Android · Web (عبر Expo)
- **اللغة/الاتجاه:** العربية · RTL
- **الوضع الافتراضي:** يعمل بالكامل دون خادم (بيانات محلية)، مع مسار إنتاج جاهز (Supabase + Moyasar).

## 1. نظرة عامة

«تألق» يتيح للمستخدم تصفّح الصالونات القريبة، اختيار خدمة وحلّاق ووقت وموقع
(في الصالون أو منزلي)، الدفع (بطاقة مدى / Apple Pay / محفظة تألق)، ثم إدارة
حجوزاته وتقييم تجربته. يشمل أيضاً **لوحة صاحب صالون** لإدارة قائمة الخدمات التي
تُنشر فوراً للعملاء.

بُني بدمج **ملف التصميم** (`docs/DESIGN.md`) مع **أجزاء أكواد** الواجهة والخدمات
المرفقة، ثم إكمالها إلى تطبيق متكامل قابل للتشغيل مباشرة.

## 2. الميزات

| الميزة | الوصف |
|---|---|
| مصادقة برقم الجوال | تسجيل دخول برقم سعودي + رمز تحقّق (OTP) — في وضع العرض أي رمز من 4 أرقام |
| تصفّح وبحث | بحث نصّي، تصنيفات (رجال/نساء/أطفال/منزلي)، مبدّل مدينة، صالونات مميّزة وقريبة |
| تفاصيل الصالون | غلاف، خدمات بأسعار، طاقم الحلّاقين، آراء العملاء، تقييم |
| تدفّق الحجز | اختيار الخدمة/الحلّاق/اليوم/الوقت/الموقع (صالون أو منزلي مع العنوان) |
| الدفع | ثلاث طرق: بطاقة مدى، Apple Pay، محفظة تألق (خصم فوري من الرصيد) |
| المحفظة | رصيد + سجل حركات (دفع/استرداد/شحن/ترويجي)، شحن فوري |
| حجوزاتي | قادمة/سابقة، إلغاء مع استرداد للمحفظة، تقييم بعد الاكتمال |
| التقييم | نجوم + وسوم (نظافة، احترافية، التزام بالموعد...) |
| لوحة صاحب الصالون | إضافة/حذف خدمات «غرفة الحبر» وتُنشر مباشرة للعملاء |
| الثيم | فاتح / داكن / تلقائي (يتبع الجهاز)، محفوظ محلياً |
| الإشعارات | تذكير محلي قبل الموعد بساعة، يُلغى عند إلغاء الحجز |
| Toast | تأكيدات فورية للعمليات (نجاح/معلومة/خطأ) |

## 5. الشاشات والتدفّقات

**تدفّق المستخدم الرئيسي:**

```
الترحيب → تسجيل الدخول → OTP → الرئيسية
   → تفاصيل الصالون → تدفّق الحجز → التأكيد والدفع → تم الحجز
        ↘ حجوزاتي (قادمة/سابقة) → تقييم / إلغاء
الرئيسية ↔ المحفظة ↔ حسابي (المدينة، الدفع، الثيم، لوحة الصالون)
```

- **حارس الدخول** في `app/_layout.tsx`: يوجّه غير المسجّل إلى `(auth)`،
  والمسجّل إلى `(tabs)`.
- **ربط لوحة الصالون بالعميل:** الخدمات المحفوظة في `dashboard.tsx` تصبح فوراً
  خدمات «غرفة الحبر» التي يحجز منها العميل (كما في §9 من دليل التصميم).

## 6. نظام التصميم

كل التوكنات في `constants/theme.ts` ومستمدّة من `docs/DESIGN.md`.

- **الألوان:** لؤلؤي (أسطح دافئة) · حبري (محايد داكن) · ذهبي (إبراز مقتصد) +
  ألوان دلالية (نجاح/تحذير/خطأ/معلومة).
- **الطباعة:** `IBM Plex Sans Arabic` بأوزان 400/500/600؛ سلّم أحجام ثابت.
- **المسافات/الزوايا:** شبكة أساس 4px؛ زوايا `sm/md/lg/xl/pill`.
- **الثيم المزدوج:** لوحتان بنفس المفاتيح (`lightColors` / `darkColors`).
  تقرأ المكوّنات اللوحة النشطة عبر `useTheme()` و `useThemedStyles(makeStyles)`.
  الوضع (فاتح/داكن/تلقائي) يُبدّل من «حسابي» ويُحفظ تحت `talluq_theme`.

## 7. إدارة الحالة والبيانات

### المتجر المركزي
`context/AuthContext.tsx` يوفّر المصادقة والبيانات عبر `useAuth()`، ويخزّن كل شيء
محلياً في `AsyncStorage` تحت مفتاح واحد **`talluq_db_v1`** (يتزامن تلقائياً عند
أي تغيير) — تماماً كما يصف دليل التصميم (§9).

### المنطق النقي (قابل للاختبار)
`lib/store.ts` يحوي مُحوّلات خالصة (بلا React) تُعيد حالة جديدة دون تعديل الأصل:
`addBooking` · `cancelBooking` · `rateBooking` · `topUp` · `attachReminder` ·
`partitionBookings`.

### قاعدة المال
كل المبالغ **بالهللة** (عدد صحيح): `10000 = 100.00 ﷼`.
- الدفع **بالمحفظة** يخصم الرصيد ويسجّل حركة خصم.
- الدفع **بالبطاقة** (مدى/Apple Pay) لا يمسّ رصيد المحفظة.
- الإلغاء يقيّد **استرداداً كاملاً** كرصيد في المحفظة (سياسة التصميم).

### شكل القاعدة المحلية
```ts
{
  phone: string | null;
  authed: boolean;
  city: string;                 // من قائمة المدن
  payMethod: 'mada'|'applepay'|'wallet';
  bookings: LocalBooking[];     // id, salon, service, barber, وقت, موقع, مبلغ, حالة, تقييم, reminderId
  adminServices: Service[];     // خدمات صاحب الصالون → غرفة الحبر
  wallet: { balance: number; transactions: WalletTransaction[] };
}
```

## 8. الإشعارات والحركة

- **تذكير بالحجز** (`lib/notifications.ts`): عند التأكيد يُجدَّل إشعار محلي قبل
  الموعد بساعة عبر `expo-notifications`، ويُلغى عند إلغاء الحجز. كل الاستدعاءات
  محميّة فلا تُعطِب التطبيق إن رُفض الإذن أو لم تُدعم المنصّة.
- **حركة الافتتاح**: ظهور تدريجي وطفو خفيف لميدالية اللوقو في شاشة الترحيب،
  وتحترم إعداد «تقليل الحركة» في الجهاز.

## 10. التشغيل والتطوير

```bash
npm install
npm start          # ثم امسح رمز QR بتطبيق Expo Go
# أو
npm run ios
npm run android
npm run web
```

> ملف `.npmrc` يضبط `legacy-peer-deps=true` تلقائياً، فلا حاجة لأي أعلام.
> في وضع العرض: سجّل الدخول بأي رقم جوال سعودي (`5XXXXXXXX`) وأي رمز من 4 أرقام.

**التجربة على الآيفون عبر Expo Go:** شغّل `npx expo start` على كمبيوترك (Windows
أو Mac)، وامسح رمز QR بكاميرا الآيفون على نفس الواي‑فاي. إن كانت الشبكة مقيّدة
استخدم `npx expo start --tunnel`.

## 11. مسار الإنتاج (Supabase + Moyasar)

الوضع الافتراضي محلي بالكامل. لتفعيل الخادم الحقيقي:

1. أنشئ مشروع Supabase وطبّق `supabase/schema.sql` (جداول + RLS + دوال
   `evaluate_refund` / `process_cancellation`).
2. انشر الدوال الطرفية في `supabase/functions/` (`create-payment`,
   `refund-payment`) واضبط مفاتيح Moyasar.
3. أضف `supabaseUrl` و `supabaseAnonKey` في `app.json` ضمن `expo.extra`.
4. بدّل شاشة الدفع إلى نسخة `integrations/backend/ConfirmBookingBackend.tsx`،
   ووصّل المحفظة بـ `hooks/useWallet`.

**مبادئ الأمان:** العميل لا يرسل المبالغ (تُحسب خادمياً)، القيود المالية في دوال
`SECURITY DEFINER`، RLS يقصر كل صف على مالكه، ومفتاح Moyasar على العميل
`publishable` فقط. التفاصيل في `supabase/README.md`.

## 12. قرارات هندسية

- **محلي أوّلاً:** يعمل التطبيق كاملاً دون خادم لسهولة التجربة، مع حفظ أكواد
  الخادم المرفقة سليمةً كمسار إنتاج موثّق.
- **منطق نقي منفصل:** فصل مُحوّلات الأعمال في `lib/store.ts` لجعلها قابلة
  للاختبار بمعزل عن الواجهة.
- **ثيم بـ token-swap:** لوحتان بنفس المفاتيح لتقليل التغيير في المكوّنات.
- **RTL:** يُفرض عبر `I18nManager.forceRTL(true)` (يحتاج إعادة تشغيل واحدة عند
  أول إقلاع)؛ صفوف العرض تستخدم `row-reverse` لضبط ترتيب القراءة العربي —
  يُنصح بالتحقّق البصري على جهاز عند أول تشغيل.
